# 01 需求与成功标准

## 用户与目标

目标用户是内容运营和审核人员。系统帮助其识别待处理素材，按照审核规则和已有排期形成无冲突、可确认的发布草稿，减少人工逐项查资料和核对时段的成本。

系统不连接真实发布渠道，也不把“草稿已保存”表述为“内容已发布”。

## 输入

单次任务输入包含：

- `material_id`：待审核素材标识；
- `requested_at`：用户要求的发布时间，必须包含时区；
- `confirmed_slot`：可选，用户明确确认的替代时段；
- `request_id`：可选，请求或确认凭据标识；
- `simulate_save_failure`：仅用于合成失败测试。

合成业务资料包括素材元数据、审核规则、已有排期和本地草稿状态。

## 输出

每次运行必须返回：

- 任务状态；
- 素材审核状态、风险原因和缺失字段；
- 原要求时段和建议时段；
- 待确认或待补充事项；
- 草稿保存状态和草稿 ID；
- 是否发布，固定为 `false`；
- 已用步数与步数上限。

## 范围

本次实现包含 CLI、真实模型接口、离线 Mock、本地业务工具、合成数据、幂等草稿存储、Trace 和自动化测试。

不包含界面、真实发布、账号鉴权、数据库、分布式锁、消息通知和生产级监控。

## 成功标准

1. 正常素材和空闲时段能够保存一份草稿。
2. 信息缺失或规则风险能够阻断，并给出可核对原因。
3. 原要求时段冲突时能够给出替代时段，但未经确认不保存替代排期。
4. 确认替代时段后必须再次查询，再保存草稿。
5. 相同请求重复执行只保留一份草稿。
6. 保存工具失败时返回失败，不声称保存成功。
7. 至少两条路径体现模型根据工具观察改变下一动作。
8. 达到工具调用或执行步数上限时返回明确的 `incomplete`。
