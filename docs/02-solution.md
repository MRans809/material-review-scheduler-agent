# 02 解决方案

## 调用流程

```text
用户输入
  ↓
模型选择一个允许动作
  ↓
工具层校验参数与业务边界
  ↓
读取素材 / 检查规则 / 查询时段 / 保存草稿
  ↓
返回结构化观察
  ↓
模型根据观察选择下一动作或结束
  ↓
代码层校正最终状态并输出 Trace
```

`ScheduleAgent` 最多执行 8 步。每一步只允许一个动作，工具结果会原样加入下一轮上下文。Trace 记录动作、参数、返回摘要、下一动作和公开的简短决策依据，不保存模型内部思维过程。

## 动态决策

模型可选择以下动作：

| 动作 | 职责 |
|---|---|
| `read_material` | 读取当前请求指定的素材 |
| `check_rules` | 检查必填字段、版权状态和禁用宣传语 |
| `query_slots` | 查询指定时段及可用替代时段 |
| `save_draft` | 保存草稿或返回已有幂等草稿 |
| `finish` | 结束并声明建议状态 |

动态路径示例：

- 18:00 空闲：查询结果为 `available`，下一动作是 `save_draft`。
- 18:00 被占用且未确认：查询结果为 `occupied`，下一动作是 `finish/pending_confirmation`。
- 18:00 被占用且用户确认 19:00：下一动作是再次 `query_slots`；19:00 空闲后才保存。
- 规则检查返回风险：停止查询档期，直接阻断。
- 保存返回失败：停止并返回失败，保留此前审核和时段检查结果。

## 强制业务边界

模型负责提议，代码负责授权：

- 工具拒绝读取当前请求以外的素材；
- 审核未通过时，保存工具必定拒绝；
- 保存替代时段时，必须与 `confirmed_slot` 完全一致；
- 保存前重新检查已有排期和草稿占用；
- 最终状态不会接受“没有成功保存却声称完成”；
- 所有输出固定 `published: false`。

这使真实模型即使产生错误动作，也只能得到结构化失败观察，不能绕过关键约束。

## 幂等设计

幂等键由 `material_id + requested_at + selected_slot` 的规范化 JSON 计算 SHA-256。相同请求再次保存时返回原 `draft_id` 和 `already_exists`，不新增草稿。时段查询会把同一幂等请求标记为 `reserved_by_same_request`，允许模型继续调用保存工具验证重复语义，而不是误判为外部冲突。

本地状态通过临时文件写入后原子替换，避免单进程写入中断留下半个 JSON 文件。它没有实现跨进程锁，因此不等同于生产数据库事务。

## 技术取舍

- 使用 Python 标准库，降低安装失败风险，便于评审直接运行。
- 未采用 Agent 框架。核心循环不足百行，原生实现更便于展示动作限制、状态校正和步数上限。
- 真实模型采用 OpenAI 兼容 JSON 接口，便于切换云模型或本地服务。
- 业务工具全部本地化并返回结构化 JSON，使测试可重复。
- 离线 Mock 根据工具观察动态选择动作，但它只证明编排与边界，不作为真实模型效果证据。

## 工具或模型失败

工具失败会进入下一轮观察，模型可以调整或结束。保存失败场景选择明确结束，因为重复保存可能造成不受控副作用。模型网络错误由执行器捕获并写入 Trace；若草稿尚未成功保存则返回 `failed`，若保存已由工具确认而最终总结调用失败，则保留 `completed` 业务事实并在完成原因中明确总结失败。推理模型单次调用超时为 90 秒。达到步数上限则返回 `incomplete`。
